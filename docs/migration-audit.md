## 4. 403 오류 — 발생 계층 후보

오류 화면·시각·URL을 받지 못해 재현하지 못했다. 원인은 **[가설]**이다.

| 계층 | 가설 | 판별 방법 |
|---|---|---|
| 브라우저 → Vercel | Vercel Deployment Protection(Preview 기본 보호, 또는 Production에도 켜짐) | 403 응답 HTML이 Vercel 로그인 화면이면 이것. 앱 함수 로그에 요청이 없음 |
| Vercel 함수 → 기업마당 | **해외 IP 차단.** 함수 기본 리전이 미국(iad1)이고 한국 공공 사이트 상당수가 해외 접속을 막음 | 수집 결과 메시지 "기업마당 API 응답 오류 (403)" — 이번 수정으로 `upstreamStatus:403`이 붙음 |
| Vercel 함수 → data.go.kr | 키 미승인·인코딩 키 사용 시 보통 200+XML 또는 401 | 이번 수정으로 "인증·서비스 오류 30 SERVICE_KEY_IS_NOT_REGISTERED" 같이 표시됨 |

조치: `vercel.json`에 `"regions": ["icn1"]`(서울) 추가. **병합 전 확인 필요**: 플랜에서 리전 지정이 허용되는지 Vercel 문서·대시보드로 확인. 인증 제거·헤더 위조는 하지 않았다.

## 5. 비활성 버튼

코드상 `disabled`가 걸리는 버튼은 "새 공고 수집"뿐이다. 수집 중에만 비활성이고 `finally`에서 복구된다. 어떤 버튼이 비활성으로 보였는지 정보가 없어 **[미확인]**. 화면 캡처와 화면 이름을 받으면 추적한다.

## 6. 남은 구조적 한계 (이번 범위 밖, 제안)

- 서버 DB가 없어 팀 공유·재접속 복원·수집 이력·"마지막 정상 수집 시각"을 서버에 남길 수 없다. 팀 사용이 목표라면 Vercel 연동 DB(Postgres 등) + 로그인이 필요하다. 비용·스키마를 정해 별도 승인 후 진행.
- 자동 수집 스케줄 없음. Vercel Cron을 쓰려면 DB가 먼저다(결과를 저장할 곳이 없음).
- 적합도 점수는 제목 키워드로 고정값(91/78/84/79/76/70)을 주는 방식. 지원자격 충족 여부는 판정하지 않는다. 규칙 기반 점수 체계는 DB 도입 후 설계 권장.
- `/api/custom-source`는 인증 없이 누구나 `.go.kr` 주소를 서버에서 호출하게 한다. 주소 검증은 있으나 남용 방지(호출 제한)가 없다.
